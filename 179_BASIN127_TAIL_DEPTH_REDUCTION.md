# Basin 127 tail-depth reduction

Date: 2026-06-05.

This note sharpens `178_BASIN127_THEORETICAL_REDUCTION_PLAN.md` by recording
which tail equations need which repeated-branch coefficients.

## Degree rule

For a tail label `(a,b)`, the column formula uses

```text
degree d = 35-a-b,
raw = coefficient degree d of q^(b-2) * t_inv.
```

The inverse unit `t_inv[0..d]` is determined by the derivative series
`fw[5],...,fw[5+d]`.  Since the repeated branch starts as

```text
w = z + s z^2 + w3 z^3 + ...
```

the coefficient `fw[5+d]` only needs repeated-branch coefficients through
`w_{5+d}`.  Thus:

```text
tail degree d  needs repeated data through w_{5+d}.
```

The three phi equations are even cheaper: `ode_constant_residual_a` uses only
`w1,...,w6`.

## Current pivot cost

The present rho3 normal form uses pivot labels

```text
u0_0, u2_1, u5_3.
```

Their tail degrees are

```text
u0_0 : d=0, needs w5
u2_1 : d=1, needs w6
u5_3 : d=2, needs w7
```

So the current normal form cannot form any N3 equations before `w7`, even
though several non-pivot labels by themselves only need `w5` or `w6`.

If a different third pivot could be proved valid on the same open chart using a
degree `0` or `1` label, the first tail certificate could be extracted from the
already completed `w6` checkpoint.  The finite column scout below shows this
does not happen on the displayed quotient.  Thus `w7` is the true minimum for
this normal form, but `w8` and `w9` may still be avoidable.

## Reduced proof target

Let `I_<=2` be generated by the three phi equations and the eight N3 equations
with tail degree at most `2`, using the same pivots `u0_0,u2_1,u5_3`.  The
first smaller theorem to test is:

```text
V(I_<=2) cap D(Delta*u1_pivot) subset V(J_displayed).
```

Equivalently, produce localized membership certificates

```text
(Delta*u1_pivot)^N * g in I_<=2
```

for the nine displayed generators `g`, or at least for enough of them to force
the three `r4` strata and then finish case-by-case.

If this fails, the next staged targets are:

```text
I_<=3: add u6_3,u5_2,u4_1,u3_0, stopping after w8.
I_<=4: add u7_3,u6_2,u5_1,u4_0, the current full script.
```

This gives a monotone sequence of certificates, so failure of `I_<=2` still
leaves useful information instead of forcing an all-or-nothing full saturation.

## Restart decision

As of the 21:08 status check, the active full run had saved recurrence only
through

```text

```

It was computing `w7`, with no partial checkpoint for that coefficient.  Since
the current pivots require `w7` even for the reduced `d<=2` certificate,
stopping before `last_index=7` would lose the in-progress work and is not
worth doing.

At the 21:31 heartbeat, `last_index` was still `6`.  The `progress.log`
heartbeat had not advanced past 21:16, but the exact process check showed

```text
99956  ...  96.2  python3 double_fiber_x0_simple_u30_basin127_sage_certificate.sage.py --saturate --jobs 4 --heartbeat-seconds 30 --time-limit-min 480
```

So this state should be interpreted as "inside a long coefficient operation",
not as a dead process.  Do not stop it before the recurrence status file
records `last_index=7`.

Once `repeated_column_status.json` records

```text

```

then stopping the full run is reasonable, because the reduced certificate can
reuse that checkpoint and avoid the full-run `w8,w9` layers.

## Reduced Sage-source audit

The Sage source now has three controls for this staged certificate:

```text
--max-tail-degree 2
--checkpoint-dir basin127_certificate_cache_tail2
--recurrence-source-dir basin127_certificate_cache
```

The source checkpoint loader accepts a longer source recurrence checkpoint
(`max_index=9`) for a shorter reduced run (`max_index=7`), truncates the saved
coefficient list, and immediately saves the truncated checkpoint into the new
cache.  This makes the reduced run resumable without continuing to depend on
the full-run cache.

For `--max-tail-degree 2`, the source builds:

```text
max_repeated_index = max(6,5+2) = 7,
3 phi equations,
8 non-pivot N3 equations with d<=2,
same saturation element Delta*u1_pivot.
```

It also explicitly checks that the required pivots

```text
u0_0, u2_1, u5_3
```

are present before forming the N3 equations.  Thus a reduced run cannot
silently use an invalid tail cutoff.

The source passed:

```text

  double_fiber_x0_simple_u30_basin127_sage_certificate.sage \
  basin127_low_tail_pivot_scout.py
```

## Low-degree pivot scout

The diagnostic script

```text
basin127_low_tail_pivot_scout.py
```

evaluates the low-tail columns at the five displayed points.  It reports:

```text
candidate labels degree <= 1:
  u4_3, u3_2, u3_3, u2_2, u1_0, u1_1

summary_nonzero_all:
  u4_3 False ['0', '0', '0', '0', '0']
  u3_2 False ['0', '0', '0', '0', '0']
  u3_3 False ['0', '0', '0', '0', '0']
  u2_2 False ['0', '0', '0', '0', '0']
  u1_0 False ['0', '0', '0', '0', '0']
  u1_1 False ['0', '0', '0', '0', '0']
```

More explicitly, at each displayed point:

```text
u0_0 = (1,0,0),   u2_1 = (*,1,0),
```

and every degree `0` or `1` candidate has third coordinate `0`.  Hence every
determinant

```text
det(u0_0, u2_1, candidate)
```

is zero.  The existing degree-2 pivot `u5_3` has third coordinate `4` and
determinant `4` at all five displayed points.

Since `159_BASIN127_CAS_SETUP_AND_DISPLAYED_BASIS_CHECK.md` verifies that
`J_displayed` is radical of length `5`, these pointwise checks are equivalent
to normal-form checks modulo `J_displayed`.  Thus the determinant of every
degree `0` or `1` third-pivot candidate lies in `J_displayed`, while the
determinant of the existing `u5_3` pivot is a unit on `J_displayed`.

Therefore the possible reduced restart should target `max_tail_degree=2`, not
`max_tail_degree=1`.
